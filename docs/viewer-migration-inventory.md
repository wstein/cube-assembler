# 3D view migration inventory

Fact base for a spike that replaces `src/client/view3d/` with `@puzlwerk/viewer`
and `core-viewer-bridge`. It changes no product code and decides nothing; the
migration remains an owner decision
([local tracking #29](https://github.com/wstein/cube-assembler/issues/29),
[owner comment 2026-11-17](https://github.com/wstein/cube-assembler/issues/29#issuecomment-6956721339)).

Sources, all read from the files named in each row:

- CubeAssembler `origin/main` = `88363742bc1fcee4fdbecc9f8ab22543b8ae7409`.
- PuzlWerk `origin/main` = `13899b373f4ecb094fbb130b1f97badd5e82c224`
  (`packages/viewer`, `packages/core-viewer-bridge`, `core/res`, `acceptance/`).

Status words: **present** (counterpart exists and covers the function),
**partial** (exists with a stated difference), **missing**, **not needed**
(stays in the app or is replaced by the viewer's own machinery).
Paths without a prefix are in CubeAssembler; `V:` is `puzlwerk/packages/viewer/src/`,
`B:` is `puzlwerk/packages/core-viewer-bridge/src/`.

## Summary

1. The 3D view takes a `CubeState` (six arrays of color strings,
   `src/cube/CubeState.res:1-8`), a size, a palette and an optional face to
   outline, plus the optional props `initialCube`, `initialMoves`,
   `initialFrame`, `publicMoves`, `onTurnStateChange`, `allowLayerMoves`,
   `stickerless` and `onClose` (`cubeView3D.tsx:24-41`). Photos, provenance and
   Orbit64 do not reach it
   (no match in `src/client/view3d` or `src/core/view`). `ArtworkReplacement`
   and `Picture` are not needed for the current 3D view.
2. The bridge does not translate CubeAssembler state. `createPlayer` takes a
   wire-v1 definition, state and appearance document as JSON text
   (`B:index.mjs:79`). No function in PuzlWerk turns a `CubeState` into them or
   back (grep over `core/`, `packages/`, `specs/`, `acceptance/`); the only
   examples are hand-built 2x2 fixtures
   (`acceptance/fixtures/cube-assembler-solved-2/export.mjs`, `facelets.mjs`).
   **A translation layer is needed.** Owner decision item 3
   ([#29 comment](https://github.com/wstein/cube-assembler/issues/29#issuecomment-6956721339))
   places it in the shared package: no app-owned adapter, missing translation
   goes into PuzlWerk beside `core-viewer-bridge` (see Gaps G1, G3, G10). The
   fixture's own provenance states the reason: a
   facelet-only state carries no piece or sticker identity, so identities are
   assigned to home slots and followed through moves
   (`acceptance/fixtures/cube-assembler-solved-2/provenance.json`, `stateLimitation`).
3. Play mode does not cover sizes 4-7 in the stage:
   `setPlayTarget` accepts only `size` 2 or 3 (`V:stage-host.ts:23`, check at
   `:68`), although the gesture core accepts 2-7 (`V:play-gesture-map.ts:17-19`).
4. The source-mesh path (`renderProfile: cubeAssemblerV1`) is blocked in the
   native scene (`V:native-projection.ts:10`, wstein/puzlwerk#87, open).
   The native scene draws its own two-radius body instead.
